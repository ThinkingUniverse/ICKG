# 0.4 与同名的 He-2026 ICKG 逐项深度对比

> **本篇目标**：在 [`0.1_vs_other_kgs.md`](./0.1_vs_other_kgs.md) 的横向总览基础上，**专门、逐项**对照与本项目最具可比性的同名工作——[He-2026 *AI-powered Immune Cell Knowledge Graph (ICKG)*](https://doi.org/10.1038/s44387-025-00060-4)（*npj Artificial Intelligence*, 2026-01-27），正面回答三个问题：
> 1. **它解决了什么问题？**
> 2. **它没有解决什么问题？**（以作者自己在 Discussion 中的自述为准）
> 3. **我们这个 ICKG 解决了什么问题？**
>
> **一句话结论**：He-2026 与本项目**出发点相同**（免疫知识碎片化、不可计算），但**路线分叉**——He-2026 把免疫文献整合成一个**面向科研的"基因集注释工具"并就此止步**（且在文中明确把临床应用列为"超出本研究范围"）；**本项目把同一类文献推进为"含临床实体、89 类有向+定量关系、逐边可溯源、机制→临床可执行"的免疫知识底座**，正好接续 He-2026 自己列出的那些局限。

---

## 〇、两者共同解决了什么问题？

He-2026 与本项目**出发点相同、范式相同**，二者共同解决的，是免疫学领域一个长期存在的基础问题：

- **共同痛点**：免疫细胞的状态、功能与调控知识**高度依赖上下文，却碎片化地散落在数以百万计的文献里**，无法被检索、计算与综合。
- **共同范式**：都用 **LLM 从 PubMed 文献中自动抽取实体与关系**，把自然语言转成**结构化的免疫细胞知识图谱**，而非依赖人工策划。
- **共同特性**：
  1. **实体-关系结构化**——把文献变成可按"实体→关系→实体"查询的图，而非关键词检索；
  2. **逐边可溯源 PMID**——每条关系都保留来源文献、可人工核验（"human verifiable"），抑制 LLM 幻觉、保证可问责；
  3. **可推理**——图结构天然支持多跳推理与机制假设生成，超越静态通路库。

> 一句话：**两者都把"读不完、算不动"的免疫文献，变成了一张"可溯源、可计算"的免疫知识图谱**。差异只在于这张图"做到哪一层、用来干什么"——这正是下面三节要回答的。

---

## 一、它解决了什么问题？

### 1.1 它针对的痛点
He-2026 的出发点与本项目一致：**免疫细胞的状态、功能与基因调控知识高度依赖上下文，却碎片化地散落在海量文献里**，难以综合成机制性理解。它进一步把这个大问题**收敛到一个非常具体的落地痛点——基因集注释（gene set annotation）**：

- 传统金标准是**过表达分析（ORA）**对照通用通路库（MSigDB Hallmarks / C7、KEGG、REACTOME、WikiPathways）。这些库是**上下文无关的（context-agnostic）**：缺乏细胞类型特异性粒度、偏向研究充分的通路（如代谢），**不适合解读单细胞 / 空间组学得到的复杂基因签名**。
- 直接用通用 LLM 做注释，则有**幻觉、不可问责、不可复现**的问题。

### 1.2 它的做法（方法学）
- **语料**：从 PubMed 检索 **2020-01 至 2024-09** 间、以 *"cell type" + "cancer immunotherapy"* 为关键词的 **24,000+ 篇摘要**。
- **实体识别（NER）**：微调 **BioBERT-Large** 分别识别基因 / 疾病 / 细胞类型（精度 87.87% / 85.23% / 61.77%）；通路短语用"规则 + 提示工程"抽取（精度 72.81%，并人工标注了约 4.8 万词的通路语料）。
- **关系抽取（RE）**：用 **Llama 3.1（70B）零样本提示**，仅推断 **activation / inhibition / no-association** 三态，保留前两者。用 KEGG（基因-基因）与 Immune Cell Atlas（基因-细胞类型）做基准，精度 77.18%–87.66%。
- **构图**：构建 **4 个细胞类型专用子图**（T / B / NK / 巨噬）。边权 = 支持该关系的摘要数；**每条边可追溯到来源 PMID**（"human verifiable"）。

### 1.3 它的成果（已验证的能力）
- **规模**：4 个子图合计 **115,701 条细胞类型特异边**（NK 24,901 / T 52,454 / B 16,722 / 巨噬 21,624），远超 KEGG 的 19,583 条。
- **可推理**：用 **PageRank** 做图推理，在 **scCRISPR（180 个 TF）** 与 **细胞因子刺激图谱（86 个细胞因子）** 两套扰动数据上预测差异表达基因（DEG），**显著优于 Hallmark 基线**，且"匹配的细胞类型子图"预测最准（证明上下文特异性确有价值）。
- **核心应用——基因集注释**：ICKG 的注释比 ORA / GSAI(LLM) **更简洁、更特异、语义更连贯**，甚至能注释**传统富集分析失败的小 / 新基因集**（如 Gavish 等未命名的 3 个 T 细胞 MP）。
- **可用性**：提供[交互式注释门户网站](https://kchen-lab.github.io/immune-knowledgegraph.github.io/)，代码与微调模型开源。

> **小结**：He-2026 解决的是"**让免疫文献可用于上下文特异、可溯源、抗幻觉的基因集注释与机制假设生成**"这一**科研侧**问题，并把它做扎实、做出了门户产品。

## 二、它没有解决什么问题？（作者在 Discussion 中的自述）

He-2026 在 Discussion / 后文中**明确、诚实地**列出了下列边界——这些正是本项目的切入点：

| # | He-2026 自述的局限 / 排除项 | 原文依据 |
|---|---|---|
| 1 | **只用摘要、未用全文**：全文有更全面的机制描述，但有解析错误、冗余、算力高等挑战，留待未来 | "our analysis was based on abstracts instead of full-text" |
| 2 | **关系仅二分 activation / inhibition**：简化便于推理，但**限制生物学粒度、掩盖上下文依赖的调控**；可纳入概率关系或扩展 binding / co-expression 等 | "tasked LLMs to dichotomize entity relationships into either activation or inhibition … the simplification can limit biological granularity" |
| 3 | **只到大细胞类型层（major cell type）**：未细化到**亚型 / 细胞状态**，因增加粒度会降低准确性与可用性 | "we currently establish the graphs at the major cell type level" |
| 4 | **文献偏倚**：过度代表**热门基因与近期文献**，缺老文献覆盖 | "tending to overrepresent frequently studied genes and recent publications" |
| 5 | **不覆盖全转录组**：源自癌症免疫聚焦的近五年摘要，富集免疫相关基因，非全转录组 | "do not capture the whole transcriptome" |
| 6 | **未构建统一全景图**：只做了 4 个**割裂子图**作概念验证，统一图的全面覆盖须权衡特异性下降与对热门细胞的偏倚 | "we did not explicitly test a unified graph encompassing all abstracts" |
| 7 | **语料局限于"癌症免疫治疗"**：关键词即为 *cancer immunotherapy*，不覆盖自身免疫 / 感染 / 疫苗 / 移植等更广免疫学 | 方法学关键词与 "cancer immunology–focused abstracts" |
| 8 | **缺临床可执行实体**：实体仅 gene / disease / cell type / pathway / protein complex / others，**无 drug / chemical / intervention** | Table 3 节点类型 |
| 9 | **临床 / 转化应用"超出本研究范围"**：机制推断、靶点优先级、细胞通讯轴、通路情境化、可检验假设等**仅在补充说明里举例**，正文只落地了基因集注释 | "these applications are beyond the scope of this current study" |
| 10 | **推理依赖 PageRank**：稀疏（低连接度）节点预测较弱 | "Sparse nodes provide few routes and result in weaker predictions" |

> **关键一句**：He-2026 自己把"**临床可执行**"和"**关系语义丰富化**"明确划在了本研究范围之外——这恰好就是本项目要补上的那一段。

## 三、我们这个 ICKG 解决了什么问题？

本项目针对 He-2026 自述的局限（尤其第 2、6、7、8、9 条），把图谱从"科研注释工具"推进到"机制→临床可执行的知识底座"：

1. **一张免疫全景异构大图**（对应局限 6、7）：不是 4 个割裂的细胞类型子图，而是一张统一的免疫全景图；语料为 **2016–2026 PubMed 免疫学文献**（时间更长、主题更广，不局限于癌症免疫治疗）。
2. **89 类有向 + 定量的关系语义**（对应局限 2）：不止 activation / inhibition，而是涵盖 *associated_with / increases / decreases / promotes / inhibits / results_in / help_identify / treatment_for* 等 **89 类带方向与定量含义**的关系，其中 **17 万+ 条有向因果边**。
3. **含临床可执行实体**（对应局限 8）：19 类实体中包含 **disease / intervention / chemical / pathology / phenotype** 等可直接对接临床动作的实体类型。
4. **机制→临床全链路闭环**（对应局限 9）：在同一张可溯源图上闭环"非结构化文献 → 可结构化检索 → 多跳因果推理 → 未知关联预测 → 临床可执行（ICI 响应预测 / 风险预测 / 报告解读）"。
5. **更适配的抽取范式**：用 **Baichuan-M2-32B 医学领域微调 + QLoRA + 结构化提示**（而非通用 Llama 3.1 70B 零样本），更契合中文医学语境与结构化输出。
6. **逐边可追溯 PMID**：与 He-2026 一致地保留可溯源性，但承载在更丰富的关系与临床实体之上。

**规模**：423,823 三元组 / 235,457 实体 / 19 类实体 / 89 类关系。

## 五、诚实的边界：两者共同的开放挑战

为避免"只夸自己"，应明确：**He-2026 的部分局限，本项目同样需要持续应对**，这些是后续迭代方向而非已完全解决：

- **文献固有偏倚**：凡基于文献抽取的图谱都会偏向热门基因与近期研究，本项目同样需要做覆盖度归一与老文献补充。
- **摘要级抽取的覆盖上限**：若以摘要为主，机制细节的完整性受限，纳入全文是共同的后续方向。
- **亚型 / 细胞状态粒度**：更细的免疫细胞亚型 / 状态级语义仍是难点。
- **KGE / GNN 推理的充分验证**：本项目主张的链接预测、ICI 响应预测等下游能力，仍需像 He-2026 用扰动数据验证 PageRank 那样，用独立金标准系统验证。

> 因此本项目相对 He-2026 的真正差异，**不在于"更准"，而在于"接续其自述局限、把图谱从科研注释推进到临床可执行"**——二者是互补的演进关系，而非替代关系。
